# 2 Detailed description of unit test strategy

The unit tests were designed using equivalence class testing, a black-box testing technique that divides the input domain into classes of data from which test cases are derived.

For each method under test, the input space was systematically analyzed and partitioned into equivalence classes. An equivalence class represents a set of valid or invalid inputs that are expected to be treated similarly by the system. If one test case in an equivalence class detects a defect, all other test cases in that class would likely detect the same defect; conversely, if one test case does not detect a defect, none of the others in that class would either.

For example, the combine method in the Range class was partitioned along the following dimensions:
- Null Status: Whether each range parameter is null or non-null
- Range Relationship: Whether the ranges are intersecting, touching, non-intersecting, or one contains the other
- Order: Whether the ranges are provided in numerical order or reverse order

These partitions resulted in 12 distinct equivalence classes, producing the following test cases:
- combine_BothRangesNull
- combine_Range1Null
- combine_Range2Null
- combine_SameRange
- combine_TouchingRangesInOrder
- combine_TouchingRangesNotInOrder
- combine_IntersectingRangesInOrder
- combine_IntersectingRangesNotInOrder
- combine_NonIntersectingRangesInOrder
- combine_NonIntersectingRangesNotInOrder
- combine_RangeInsideRangeInOrder
- combine_RangeInsideRangeNotInOrder

This systematic approach ensures comprehensive coverage of the method's behavior across all meaningful input variations while maintaining an efficient and manageable test suite.
